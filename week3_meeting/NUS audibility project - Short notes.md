## **C2PA technical validation and research findings**

* Leon confirmed C2PA supports custom JSON embedding but noted significant limitations in non-media file types like PDF and Word.  
* C2PA implementation faces challenges with data serialization requirements and potential file corruption in specific scenarios.  
* Adobe's ownership of the PDF format appears to restrict C2PA interoperability, preventing native writing support for those files.  
* Leon successfully extracted signature data from Google Gemini-generated images, confirming established C2PA integration in industry tools.

## **Strategic positioning of MSD versus C2PA**

* Ulf distinguished between C2PA's file-level metadata embedding and MSD's broader concept of enterprise-wide provenance tracking.  
* The group analyzed whether C2PA acts as a direct competitive threat or if the two schemes function as orthogonal, parallel standards.  
* Josh emphasized the necessity of a concise, user-centric pitch that clearly articulates MSD's distinct advantages regarding internal auditability and complex workflows.

## **Expansion of MSD use cases and AI agent protocols**

* Lamphare identified Visa's Trust Agent Protocol (TAP) as a reference point for applying MSD to verify AI agent actions.  
* The team discussed broadening the potential scope of MSD to include AI agents as users, rather than limiting the protocol to human-centric signing.

## **Tooling and verification roadmap**

* Ulf highlighted the critical need for enterprise tooling that handles trust verification without requiring manual, high-effort user intervention.  
* Josh and Leon established a requirement to investigate how C2PA signatures point to public keys to validate the authenticity of origin claims.  
* The group prioritized investigating file interlinkability features in MSD to differentiate the scheme from the C2PA standard.
